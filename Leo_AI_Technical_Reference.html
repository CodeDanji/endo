1. 개요 및 구동 원리 (Architecture & Mechanisms)

🧠

Large Mechanical Model (LMM)

일반 범용 LLM(ChatGPT, Claude 등)과 달리, 기계공학 도메인 지식과 CAD Topology에 특화된 고유 AI 아키텍처입니다.


  • 100만+ 전문 출처 학습: ISO, ASME, DIN, MIL-SPEC 등 표준 규격서, 재료 물성 데이터, 기계요소 설계 도서 인덱싱.
  • 3D Geometry & Topology 인식: 메타데이터 뿐만 아니라 3D B-rep(Boundary Representation) 형상 그래프(Face, Edge, Vertex)를 직접 연산.
  • 수학적/물리적 제약조건 통합: 응력/하중, 재질 밀도, Machining Tolerance 등 물리 제약조건 기반 추론.
⚙️

B-rep 기반 CAD 생성 메커니즘

기존 AI의 메쉬(Mesh, STL/OBJ) 생성이 갖는 한계를 극복하고 CAD 프로그램 호환 파라메트릭 피처 트리를 생성합니다.


  • Parametric Feature Tree 생성: Extrude, Revolve, Fillet, Hole 등 편집 가능한 CAD 스크립트 명령(Command Sequence)으로 변환.
  • CSG & Constraint Solver 연동: 2D 스케치 제약 조건(동심, 평행, 수직 등)을 수학적으로 풀이하여 B-rep Solid 모델링.
  • Native CAD Engine 호환: SolidWorks, Onshape, Fusion 360 등 기존 CAD 커널에서 직접 수정 가능.

Part Reuse (부품 재활용)

Real-time DFMA Inspection

5. 장단점 및 한계 분석 (Pros & Cons)

👍 핵심 장점 (Advantages)

  • 피처 트리 살린 B-rep CAD 출력: 메쉬 덩어리가 아닌 CAD 커널 수정 가능 모델 생성.
  • 출처 제시를 통한 높은 신뢰성: 답변 시 표준 규격 문서 조항 Citation 표기로 환각 최소화.
  • 기존 CAD 환경 유지: 별도 툴 이동 없이 SolidWorks/Fusion 360 내에서 바로 구동.
  • BOM 비용 절감: 형상 기반 부품 재활용(Part Reuse)으로 중복 발주 차단.

👎 한계 및 고려사항 (Limitations)

  • 사내 PDM 데이터 상태 의존성: PDM 데이터 정리가 안 되어 있으면 부품 검색 성능 저하.
  • 엔지니어 검증 필수 (Copilot 개념): 완벽한 자율 설계가 아니므로 물리적 최종 검증은 필수.
  • 초기 구축 비용: Enterprise 환경의 PDM API 구축 및 보안 인증에 일정 비용/시간 소요.

# 2. LLM Code Generation & Dynamic Execution Loop
def execute_ai_generated_cad_script(python_code_str):
    # DFMA 및 안전성 검증 후 exec() 구동
    exec_globals = {"adsk": adsk, "app": adsk.core.Application.get()}

  • Step 1. Fusion 360 Custom Palette 탑재: `ui.palettes.add()`를 사용하여 CAD 사이드바에 웹패널 탑재.

  • Step 3. DFMA Validation Check: 코드 실행 전 최소 두께, 간섭 및 구멍 깊이 비율 사전 사양 검증.

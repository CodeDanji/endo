1. 개요 및 핵심 비전 (Overview & Core Vision)
Core Concept
🚀 Zoo (zoo.dev) 란?

Zoo(구 KittyCAD)는 폐쇄적인 바이너리 파일과 전통적 GUI 위주의 CAD 환경을 탈피하고, 코드 중심(Code-First) & 클라우드 네이티브 파라메트릭 CAD 인프라를 구축하는 차세대 하드웨어 설계 플랫폼입니다.

🎯 비전 & 핵심 가치

"하드웨어 설계는 소프트웨어 개발만큼 프로그래머블하고 개방적이어야 한다."
Git을 통한 버전 관리, 코드 차이점 비교(Diff), 자동화 테스트(CI/CD), AI 에이전트를 CAD 설계 워크플로우에 완벽 통합합니다.

👥 타겟 사용자층
  • 기계/하드웨어 엔지니어: 파라메트릭 및 코드 기반 설계자
  • 소프트웨어 개발자: CAD 자동화 툴 및 Web 3D 커스텀 앱 개발자
  • 로봇공학자 & AI 연구원: 정밀 3D 모델링 생성 및 자동화 검증 엔지니어
2. 지오메트리 엔진 & 수학적 아키텍처 (Geometry Kernel)
GPU Native Kernel
📐 레거시 C++ 커널 vs Zoo GPU-Native Kernel 비교

기존 레거시 CAD 커널(Siemens Parasolid, Dassault ACIS, OpenCASCADE 등)은 1980~1990년대에 설계되어 단일 쓰레드 CPU 연산에 의존하며, 메모리 관리가 취약하고 병렬화가 어렵습니다. Zoo는 Rust 언어로 처음부터 재작성하여 GPU 가속(Vulkan / WebGPU) 및 스레드 안전성을 확보했습니다.

B-Rep 위상 구조 (Topology)

Polygon Mesh(STL/OBJ)의 모호한 정점 집합이 아닌 Solid -> Shell -> Face -> Loop -> Edge -> Vertex 정밀 B-Rep 구조를 GPU 데이터 구조체로 직접 매핑하여 연산합니다.

GPU 가속 SSI (Surface-Surface Intersect)

NURBS 곡면 간 교차선을 구하는 SSI 연산을 GPU 병렬 컴퓨팅 셰이더로 수천 개 레이를 동시에 교차 계산하여 불리언 연산(Combine/Cut) 속도를 수십 배 향상시킵니다.

메모리 안전성 & WASM 컴파일

Rust의 Strict Ownership 개념으로 Pointer/Buffer Overflow 및 race condition을 근본 차단하며, 동일 코드를 WebAssembly(WASM)로 컴파일하여 브라우저 로컬에서도 로직을 사전 평가합니다.

3. KCL (KittyCAD Language) 컴파일러 & 구문 스펙
Compiler Spec
💻 KCL 파이프라인 및 파이프 연산자(`|>`) 매커니즘

KCL은 파라메트릭 기하 정의에 최적화된 함수형/선언형 믹스 언어입니다. 파이프 연산자(|>)와 플레이스홀더(%)를 활용하여 이전 기하 개체를 다음 모델링 명령의 입력으로 투명하게 전달합니다.

KCL 컴파일 단계 (Compilation Stages)

  1. Lexing & Parsing: KCL 소스코드를 토큰화하여 AST(Abstract Syntax Tree) 구축
  2. Constraint Solving: 2D 스케치 내의 미결정 구속조건(Underspecified constraints)을 수치 솔버가 자동으로 풀이
  3. IR Generation: 플랫폼 독립적 Modeling Command IR(중간 표현) 생성
  4. Engine Execution: WebSocket을 통해 Cloud Kernel로 명령 패킷 전송

주요 언어적 특성 (Language Features)

  • Variables & Units: const r = 15mm (단위 자동 변환 지원)
  • Sketch Plane Binding: startSketchOn('XY') 또는 startSketchOn(face)
  • Solid Operations: extrude, revolve, sweep, loft
  • Feature Array: patternLinear3d, patternCircular3d

📜 KCL 프로그래밍 예제: 복합 플랜지 부품 (Flange Component)

// 1. 설계 파라미터 및 단위 정의
const outerRadius = 50mm
const innerRadius = 25mm
const flangeThickness = 12mm
const boltCircleRadius = 38mm
const boltCount = 6
const boltHoleRadius = 4mm

// 2. 기본 플랜지 바디 스케치 및 압출
baseProfile = startSketchOn('XY')
  |> circle(center = [0, 0], radius = outerRadius, %)
  |> hole(circle(center = [0, 0], radius = innerRadius, %), %)

flangeBody = baseProfile |> extrude(flangeThickness, %)

// 3. 원형 배열을 이용한 볼트 구멍 타공 및 필렛 처리
boltHoleCutout = startSketchOn(flangeBody, 'END')
  |> circle(center = [0, boltCircleRadius], radius = boltHoleRadius, %)
  |> extrude(-flangeThickness, %)
  |> patternCircular3d(axis = [0, 0, 1], count = boltCount, center = [0, 0, 0], %)

// 4. 모서리 R2mm 필렛(Fillet) 적용하여 최종 반환
finalPart = boltHoleCutout |> fillet(radius = 2mm, tags = ['outerEdges'], %)
4. Text-to-CAD Agentic ML 파이프라인 (Zookeeper)
AI Architecture
🤖 Plan-Act-Observe-Update 피드백 루프

Zoo의 AI 에이전트 Zookeeper는 단순 원샷(One-shot) 텍스트 생성이 아닌, 자가 진단 및 피드백 루프를 구동합니다.

  1. Plan: 사용자 프롬프트에서 부품 치수, 기하학적 형상 구속 조건 파악
  2. Act: 초안 KCL AST 파싱 및 KCL 소스 코드 생성
  3. Observe: Cloud Geometry Engine으로 KCL 실행 후 비정상 위상(Self-intersection, Open Profile)이나 컴파일 에러 수집
  4. Update: 컴파일 오류 메시지와 기하 실패 결과를 LLM 컨텍스트에 재투입하여 자가 수정(Self-Correction) 반복
📦 B-Rep (STEP) vs Mesh Generative AI 비교

대다수 3D AI(Midjourney 3D, Meshy 등)는 메시(Mesh/Point Cloud) 형태의 모호한 표면 껍데기만 출력하여 CAD 수정이 불가능합니다.

Zoo의 B-Rep 생성 우위성:
1. STEP / IGES 표준 산업 포맷 완벽 호환
2. CNC 가공 공구 경로(G-code) 및 CAM 연동 가능
3. KCL 파라미터만 고치면 치수(Dimension) 즉시 수정

6. 주요 사용 방법 (Usage & Client SDKs)
How to Use
🖥️ Zoo Design Studio (GUI + Code)

GUI + Code 듀얼 인터페이스:
화면 한쪽의 3D 뷰포트에서 마우스 클릭으로 스케치하면 반대쪽 코드 창에 KCL 코드가 실시간 자동 작성되고, 반대로 KCL 코드를 직접 입력하면 3D 뷰포트가 실시간 업데이트됩니다.

💬 Text-to-CAD (AI 대화창)

자연어 프롬프트 입력:
Zookeeper AI 대화창에 "두께 5mm, 모서리 4곳에 M4 나사 구멍이 뚫린 100x60mm 마운팅 플레이트를 만들어줘" 와 같이 입력하면 완벽히 파라메트릭화된 모델이 즉시 생성됩니다.

10. CI/CD 파이프라인 자동화 예시 (GitHub Actions)
Automation
🔄 Git Commit 시 하드웨어 CAD 치수 & 질량 자동 검증

Zoo CLI를 사용하면 소프트웨어 CI/CD처럼 Git Push 발생 시 KCL 부품의 질량이 허용 범위를 초과하는지 자동 파이프라인 검사를 수행할 수 있습니다. 

# .github/workflows/cad-validation.yml
name: CAD Automated Quality Gate

on: [push, pull_request]

jobs:
  validate-hardware:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Install Zoo CLI
        uses: KittyCAD/action-install-cli@v1

      - name: Check KCL Part Mass & Volume
        env:
          ZOO_API_TOKEN: ${{ secrets.ZOO_API_TOKEN }}
        run: |
          zoo mass models/flange.kcl --material aluminum-6061 --max-mass 150g
          zoo export models/flange.kcl --format step --output dist/flange.step
11. 장단점 심층 분석 (Pros & Cons)
Comparison
👍 장점 (Key Advantages)
  • Git 친화적 코드 관리: 바이너리가 아닌 텍스트(KCL)로 모델이 저장되어 Git PR, Diff, Branching이 완벽하게 구동됨.
  • 정밀 제조용 B-Rep AI: 단순 폴리곤 메시가 아닌 STEP 변환이 가능한 정밀 파라메트릭 CAD 모델 생성.
  • 클라우드 GPU 가속: 저사양 컴퓨터나 브라우저에서도 WebRTC 비디오 스트리밍을 통해 고성능 3D 조작 가능.
  • 완벽한 개방형 API 생태계: REST, WebSocket, CLI 및 4개 국어 SDK 지원으로 파이프라인 자동화 용이.
  • 실시간 양방향 동기화: GUI 조작과 KCL 코드 간의 오차 없는 실시간 반영.
⚠️ 단점 및 한계점 (Limitations)
  • 인터넷 연결 필수: 지오메트리 엔진 및 렌더링이 클라우드 GPU에서 구동되므로 오프라인 사용 제약.
  • 생태계 성숙도 격차: SolidWorks, Fusion 360 대비 complex assembly, FEA 시뮬레이션, 고급 CAM 연동 기능은 아직 발전하는 과정임.
  • KCL 프로그래밍 학습 곡선: 마우스 클릭 중심의 레거시 CAD 사용자에게는 코딩 방식에 적응할 시간이 필요함.
  • 네트워크 지연 영향: 네트워크 품질에 따라 WebRTC 스트리밍 및 반응 속도의 미세한 차이 발생.

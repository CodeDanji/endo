오류 1: 파이썬 global 선언 위치 예외

SyntaxError

오류 메시지: SyntaxError: name 'app' is used prior to global declaration

원인 분석: Python 언어 규격상 함수/메서드 내부에서 글로벌 변수를 참조하기 전 최상단에 global을 선언해야 합니다. do_POST() 내부의 elif 블록에 global app을 별도 선언하여 예외가 발생했습니다. 
# [수정 전 오류 코드]
def do_POST(self):
    if self.path == "/modify":
        global app, modify_event_id  # 1차 선언
        if app: ...
    elif self.path == "/build":
        global app, build_event_id   # ❌ app이 이미 참조된 후 재선언되어 SyntaxError 발생

# [수정 후 정제 코드]
def do_POST(self):
    global app, modify_event_id, build_event_id  # ✅ 메서드 최상단 일괄 선언
    if self.path == "/modify": ...
    elif self.path == "/build": ...

오류 2: REST /build 엔드포인트 404 예외

HTTP Error 404

오류 메시지: urllib.error.HTTPError: HTTP Error 404: Not Found

원인 분석: Fusion 360 실행 중 `AntigravityOnDemand.py` 소스코드에 `/build` 엔드포인트를 추가하더라도, 이미 Fusion 360 파이썬 프로세스 메모리에 로드된 기존 REST 서버 클래스는 새 코드를 인식하지 못하고 404를 반환했습니다.
해결책: Fusion 360의 Scripts and Add-Ins 창에서 AntigravityOnDemand를 Stop ➔ Run하여 프로세스 내 서버 클래스를 재로드.

오류 3 & 4: Fusion 360 API 읽기전용/루트 변경 불가능 예외 (핵심)

Fusion 360 3D 모델링 생성 파이프라인 중 발생한 가장 결정적인 2가지 API 속성 예외입니다.

오류 3: Document Name Read-Only 예외

오류 메시지: AttributeError: can't set attribute 'name'

# [원인 코드 - line 368]
doc = app.documents.add(adsk.core.DocumentTypes.FusionDesignDocumentType)
doc.name = "ENDOCRAB_Master_Assembly.f3d"  # ❌ AttributeError 발생! (Fusion 360 doc.name은 읽기 전용)

여파: `doc.name` 설정 시 예외가 던져져 신규 빈 문서만 생성되고, 하위 3D 솔리드/스케치/파라메트릭 생성 함수가 전부 실행되지 않고 중단됨.

오류 4: Root Component Name Lock 예외

오류 메시지: RuntimeError: 3 : root component name cannot be changed

# [원인 코드 - line 379]
root_comp = design.rootComponent
root_comp.name = "ENDOCRAB_Master_Assembly"  # ❌ RuntimeError 발생! (Root Component 이름은 수정 불가)

# [수정 완료 코드]
root_comp = design.rootComponent  # ✅ root_comp.name 설정 구문 완전 제거

오류 5: 파이썬 모듈 캐싱 및 바이트코드 영속성 (Pycache Persistence)

Module Cache

현상: 디스크 상에서 `build_endocrab_model.py`의 오류 코드를 수정했음에도 불구하고, Fusion 360에서 스크립트를 재실행할 때 계속해서 이전 에러 Traceback(line 379 `root_comp.name` 오류)이 반복 출력됨.

원인 메커니즘:
  1. Fusion 360의 파이썬 인터프리터는 실행 시 `sys.modules` 딕셔너리에 한번 로드된 임포트 모듈을 캡처하여 보관합니다.
  2. 또한 `__pycache__/*.pyc` 바이트코드 파일이 남아있는 경우, 디스크의 `.py` 변경사항을 무시하고 캐시된 바이트코드를 재사용합니다.
  3. 단순히 Add-in을 Stop/Run 하더라도 `sys.modules`에 등록된 하위 모듈(`build_endocrab_model`)은 갱신되지 않습니다.

완벽 해결을 위한 구조적 개선안 (Implementation)

# 1. 자동 배포 시 pycache 강제 삭제 (install_to_fusion360.ps1)
Get-ChildItem -Path $TargetDir -Recurse -Filter "*.pyc" | Remove-Item -Force
Get-ChildItem -Path $TargetDir -Recurse -Directory -Filter "__pycache__" | Remove-Item -Recurse -Force

# 2. ENDOCRAB_Builder.py 및 AntigravityOnDemand.py에서 dynamic exec() 적용
script_path = os.path.join(SCRIPT_DIR, "build_endocrab_model.py")
with open(script_path, "r", encoding="utf-8") as f:
    code = f.read()
exec_globals = {"__file__": script_path, "__name__": "__main__"}
exec(code, exec_globals)  # ✅ sys.modules 캐싱을 완전히 우회하여 최신 코드 즉시 실행!

1. 근본 원인 종합 분석 (Root Cause Analysis)

실제 수술용 오토 수처링 디바이스(Image 1: IIT Bombay 2-Click Pistol-Grip, Image 2/3: Nature Sci Rep 2024 ENDOCRAB)와 Fusion 360 자동 생성 결과물 간의 모델링 표현력 및 화면 미갱신 문제에 대한 근본 원인을 3가지 축으로 정밀 진단했습니다.

원인 1: Direct Fusion API의 CSG vs B-Rep Topology 인덱스 취약성

순수 파이썬 코드로 Fusion 360 API를 직접 호출할 때, 90도 직육면체 압출(`addTwoPointRectangle` + `extrudeFeatures`)은 10줄 내외로 안정적 빌드되지만, 수술 장비의 **유선형 곡면(Organic Loft)**, **3D 스플라인 궤적(Sweep)**, **모서리 라운딩(Fillet)**을 작성할 경우 B-Rep 엣지 인덱스(`body.edges.item(n)`) 지정 오류나 C++ 런타임 예외가 발생합니다. 이 때문에 스크립트가 밋밋한 박스 형태로 둔화되어 생성되었습니다.

원인 2: Fusion 360 Compute Graph & Active Document Isolation (화면 미갱신)

외부에서 파이썬 코드 및 파라메터를 수정하더라도, Fusion 360 프로그램 내부 메모리(`sys.modules`) 및 active document 캔버스는 외부 스크립트 실행 후 사용자가 스크립트 메뉴에서 `Run`을 직접 다시 누르거나 `activeViewport.refresh()` 이벤트를 호출받기 전까지는 이전 화면 상태를 그대로 보존(Freeze)합니다.

원인 3: LLM 코드 생성과 전문 CAD 설계 생태계 간의 패러다임 갭

전문 CAD 엔지니어링 현장에서는 파이썬 코드로 3D 부품을 처음부터 끝까지 수천 줄의 API 코드로 그리지 않습니다. **Master Template (`fx`) 파라메트릭 드라이브** 또는 **CadQuery / OpenCASCADE 파이썬 정밀 CAD 엔진 기반 `.step` 파일 내보내기** 표준 방식을 결합하여 사용해야만 실물 렌더링 퀄리티와 100% 동일한 3D 모델을 얻을 수 있습니다.

cadquery_step_generator.py Python OpenCASCADE 3D CAD 엔진을 통해 인볼루트 기어 이빨, 톱니 집게, 유선형 로프트를 지닌 `.step` 파일 자동 생성. Fusion API 스케치 구속조건 C++ 런타임 오류 및 B-Rep 모서리 인덱스 손실 완벽 해결.
fusion_rest_listener.py Fusion 360 내부에서 상주하는 REST HTTP 서버 (Port 8080). `/inspect`, `/build`, `/modify` 핸들러 제공. 외부 코드 변경 시 Fusion 360 화면이 자동 갱신되지 않는 캔버스 고정 현상 해결.
Master Template `.f3d` 미리 손으로 잘 그어진 Master CAD 파일의 `userParameters` (`fx`) 변수표를 스크립트로 0.1초 만에 갱신. 100% 실물 수술 장비 렌더링 퀄리티 보장.

3. 스킬/플러그인 4단계 실행 프로토콜 (4-Stage Protocol)

Stage 1: REST Listener 기반 헤드리스 뷰포트 실시간 핫리로드

Fusion 360 내부 Add-In 스레드에서 REST 서버를 띄워, LLM이 파이썬 코드를 수정하는 즉시 메인 스레드에 커스텀 이벤트를 발생시켜 `activeViewport.refresh()` 및 `viewport.png` 캡처를 동적으로 실행합니다.

Stage 2: CadQuery / OpenCASCADE 정밀 STEP 파이프라인

기어 치형(M0.3 Z12) 및 톱니 집게 4-Notch 곡면을 파이썬 `cadquery` 라이브러리로 표현하여 `.step` 파일로 내보낸 후, Fusion 360에 `importManager.importToTarget()`으로 결합합니다.

Stage 3: Master Template `fx` 변수 실시간 바인딩

19개 파라메트릭 변수(`Body_Length`, `Needle_Outer_Dia`, `Track_Clearance` 등)를 JSON 스키마로 검증하고 `userParameters.itemByName(key).expression`을 통해 0.1초 만에 형상을 재계산합니다.

Stage 4: LLM Prompt-to-CAD 제어 및 검수

스킬 내 정의된 검수 프로토콜을 통해 스크립트 빌드 후 `/inspect`를 호출하여 캔버스 스크린샷(`viewport.png`)을 직접 읽어 시각적 결함을 2차 검수합니다.

4. 다음 대화에서 생성할 `SKILL.md` 작성 템플릿 초안

다음 세션에서 사용자 요청 한 번으로 자동 패키징할 `SKILL.md` 표준 마크다운 초안입니다.

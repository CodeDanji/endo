  • src/fusion360_mcp_server.py: AI 에이전트가 호출할 수 있는 표준 MCP(Model Context Protocol) 브릿지 서버입니다.

치명적 문제점 (사용자 페인포인트): 현재 AI는 부품을 각자 맹목적으로 절대 좌표에 그리는 '바텀업(Bottom-up) 조립'을 하고 있습니다. 이로 인해 조인트(Joint)가 어긋나고 기구학적 모션이 붕괴됩니다. 또한 코드가 실패해도 콘솔창에 에러만 뜨고 AI에게 에러 텍스트가 돌아가지 않아 스스로 버그를 고치는(Self-repair) 능력이 불가능한 상태입니다.

궁극적 목표: AI가 "탑다운(Top-down) 및 관절 중심 설계"를 강제하도록 구조를 개편하고, 실행 중 발생하는 에러(Traceback) 및 3D 위상 데이터(B-Rep Topology)를 AI의 MCP 도구 반환값으로 피드백해주는 완전 자동화 자가 치유(Self-Repair) 루프를 구현하는 것입니다.

2. 현재 시스템 동작 원리 (As-Is)

1. AI가 fusion360_execute_code(code) MCP 도구를 호출함.

2. MCP 브릿지가 http://localhost:8080/execute_code로 POST 요청 전송.

3. Fusion 360 Add-in이 코드를 비동기 Custom Event 메인 스레드에서 exec(code)로 실행.

4. 실행 직후 /inspect(GET)를 통해 화면을 캡쳐하고 state.json을 바탕화면 임시 폴더에 씀.

5. MCP 브릿지가 이를 읽어 AI에게 리턴함.

* 문제점: exec(code)가 실패해도 traceback을 저장하지 않으며, /inspect는 단순히 스크린샷과 파라미터만 던져줍니다.

태스크 3: AI를 위한 Top-down Assembly 스킬(프롬프트) 파일 생성

생성 대상 src/skills/fusion360_topdown_assembly/SKILL.md

AI 에이전트(혹은 서브에이전트)가 모델링 코드를 짤 때 반드시 참고해야 할 마크다운 문서를 새로 생성하십시오. 문서에는 다음 세 가지 Rule이 반드시 포함되어야 합니다.

  • Rule 1. Skeleton First: 부품을 그리기 전에 조인트가 위치할 중심 좌표(Pivot)를 adsk.core.Point3D 형태의 전역 변수 배열로 가장 먼저 선언하라.
  • Rule 2. No Blind Geometry: 절대 좌표 이동(Matrix3D translation)으로 맹목적 배치를 하지 말고, 반드시 생성한 컴포넌트 간에 adsk.fusion.Joints.add() API를 사용하여 기구학적 구속을 걸어라.
  • Rule 3. Self-Repair: fusion360_execute_code 반환값에 Traceback 에러가 포함되어 있다면 절대 멈추거나 사용자에게 질문하지 말고, 스스로 코드를 고쳐 에러가 안 날 때까지 재귀적으로 코드를 재전송하라.
